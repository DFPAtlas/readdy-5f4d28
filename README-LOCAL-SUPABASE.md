# DFP UAT Agent — Local Supabase Setup Guide

This guide covers connecting the DFP UAT Agent to a locally hosted Supabase instance for persistent storage, evidence management, realtime updates, and user authentication.

---

## 1. Prerequisites

- Node.js 22+ and npm
- Supabase CLI (`brew install supabase/tap/supabase` or `npm install -g supabase`)
- Docker (required for local Supabase)
- Git access to the DFP UAT Agent repository

---

## 2. Starting Local Supabase

```bash
# From the project root, start the local Supabase stack
supabase start
```

This starts PostgreSQL, PostgREST, GoTrue (auth), Storage, Realtime, and Supabase Studio — all locally.

The default ports are:
- API: `http://localhost:54321`
- Database: `localhost:54322`
- Studio: `http://localhost:54323`
- Inbucket (email): `http://localhost:54324`

---

## 4. Creating `.env.local`

Copy the example and fill in your local Supabase values:

```bash
cp .env.example .env.local
```

Update these variables in `.env.local`:

```env
VITE_PUBLIC_SUPABASE_DEPLOYMENT_MODE=local
VITE_PUBLIC_SUPABASE_URL=http://localhost:54321
VITE_PUBLIC_SUPABASE_ANON_KEY=<your-anon-key-from-supabase-status>

# Server-only — NEVER commit these
SUPABASE_SERVICE_ROLE_KEY=<your-service-role-key>
SUPABASE_DB_URL=postgresql://postgres:postgres@localhost:54322/postgres
SUPABASE_STUDIO_URL=http://localhost:54323

# Storage buckets
VITE_PUBLIC_UAT_EVIDENCE_BUCKET=uat-evidence
VITE_PUBLIC_UAT_REPORT_BUCKET=uat-reports
VITE_PUBLIC_UAT_TRACE_BUCKET=uat-traces

# Realtime
VITE_PUBLIC_ENABLE_UAT_REALTIME=true

# Database behaviour
VITE_PUBLIC_UAT_DATABASE_REQUIRED=false
VITE_PUBLIC_UAT_DATABASE_TIMEOUT_MS=10000
VITE_PUBLIC_UAT_AUTO_RUN_MIGRATIONS=false
VITE_PUBLIC_UAT_ALLOW_DATABASE_RESET=false
```

## 5. Reviewing and Applying Migrations

Review the migration file before applying:

```bash
cat supabase/migrations/20260729000000_initial_uat_schema.sql
```

Apply migrations:

```bash
supabase migration up
```

This creates all 13 UAT tables, indexes, constraints, and **Row Level Security (RLS)** policies. Anonymous users have zero access. Only authenticated staff users can access UAT data.

## 7. Generating TypeScript Types

After migrations are applied, regenerate the database types:

```bash
supabase gen types typescript --local > src/lib/supabase/database.types.ts
```

Or use the npm script:

```bash
npm run db:types:local
```

This replaces the placeholder types file with the actual schema types.

## 9. Verifying RLS and Private Storage

### Check RLS is enabled

In Supabase Studio → SQL Editor:

```sql
SELECT tablename, rowsecurity
FROM pg_tables
WHERE schemaname = 'public' AND tablename LIKE 'uat_%';
```

All UAT tables should show `rowsecurity = true`.

### Create private storage buckets

```bash
supabase storage bucket create uat-evidence --private
supabase storage bucket create uat-reports --private
supabase storage bucket create uat-traces --private
```

These buckets are **private** — no anonymous uploads or public URLs. Evidence is accessed through short-lived signed URLs generated by the backend.

## 10. Testing Realtime

Realtime is enabled by default when `VITE_PUBLIC_ENABLE_UAT_REALTIME=true`.

To verify:

1. Open the UAT Agent at `/staff/uat-agent`
2. Start a test run
3. Open the Supabase Studio → Realtime inspector
4. You should see a subscription to the run's channel

When Realtime is unavailable, the frontend automatically falls back to polling with a "degraded live updates" notice.

## 11. Connecting n8n

n8n needs to save UAT results into your local Supabase. Use the **Supabase node** or direct API calls.

Credentials for n8n:
- **API URL**: `http://localhost:54321` (or your LAN address for Docker)
- **Service Role Key**: from `SUPABASE_SERVICE_ROLE_KEY` in `.env.local`
- **Anon Key**: from `VITE_PUBLIC_SUPABASE_ANON_KEY` in `.env.local`

⚠️  Never put these credentials into the n8n workflow JSON. Store them in n8n credentials or environment variables.

n8n operations:
- `POST /rest/v1/uat_test_runs` — Create/update test runs
- `POST /rest/v1/uat_journey_results` — Create journey results
- `POST /rest/v1/uat_agent_findings` — Add findings
- `POST /rest/v1/uat_bug_reports` — Upsert bugs
- `POST /rest/v1/uat_bug_occurrences` — Add bug occurrences
- `POST /rest/v1/uat_bug_evidence` — Add evidence metadata
- `POST /rest/v1/uat_audit_log` — Record audit events

## 13. Backing Up Before Migrations

Always back up before applying new migrations:

```bash
# Dump the local database
supabase db dump --local --data-only > backup-$(date +%Y%m%d).sql

# Apply migrations
supabase migration up

# If something goes wrong, reset and restore:
# supabase db reset
# psql postgresql://postgres:postgres@localhost:54322/postgres < backup-YYYYMMDD.sql
```

## 14. Switching to Hosted Supabase

To switch from local to hosted Supabase (e.g., supabase.com):

1. Update `.env.local`:

```env
VITE_PUBLIC_SUPABASE_DEPLOYMENT_MODE=hosted
VITE_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
VITE_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...  # from Supabase dashboard
SUPABASE_SERVICE_ROLE_KEY=sb_secret_...        # from Supabase dashboard
```

2. Push migrations to hosted:

```bash
supabase link --project-ref your-project-ref
supabase db push
```

3. Create storage buckets in the Supabase dashboard.

4. Regenerate types:

```bash
supabase gen types typescript --linked > src/lib/supabase/database.types.ts
```

5. Rebuild:

```bash
npm run verify
npm run build
```

## 15. Troubleshooting

| Problem | Solution |
|---------|----------|
| `supabase start` fails | Ensure Docker is running. Check `docker ps` for existing containers. |
| Migrations fail | Check `supabase migration list`. Reset with `supabase db reset` (local only). |
| Types are stale | Run `npm run db:types:local` to regenerate. |
| RLS blocks access | Verify you are authenticated as a staff user. Check `is_staff_user()` function. |
| Storage buckets missing | Create them: `supabase storage bucket create uat-evidence --private` |
| Realtime not working | Check `VITE_PUBLIC_ENABLE_UAT_REALTIME=true`. Verify Supabase Realtime is enabled. |
| "Permission denied" on tables | RLS is active. Staff must be authenticated. Check `app_metadata.role`. |
| Port conflicts | Change ports in `supabase/config.toml` and update `.env.local` accordingly. |

# Test generation
curl -s http://192.168.1.92:11434/api/generate \
  -H "Content-Type: application/json" \
